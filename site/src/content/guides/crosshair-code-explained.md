## 准星码是什么

CS2 里分享准星的方式是一串 **`CSGO-` 开头的 34 字符文本**，形如：

```
CSGO-UseJt-3oTvn-47wPX-hEyER-WZfiK
```

结构是 `CSGO-` 加上 5 组、每组 5 个字符，用连字符分隔。字符集只包含大小写字母、数字和连字符（刻意剔除了 `0/O`、`1/l/I` 这类易混淆字符），所以它既是定长的、也是 URL 安全的 —— 这也是本站能给每个准星码单独开一个页面的原因。

它不是标准 base64，也不是 protobuf：解码时用一个自定义的 55 字符字典把整串当作大整数还原成约 19 字节的定长二进制，再按位拆出各个参数。

## 21 项参数

准星码携带**完整的 21 项**参数。下面按作用分组说明。

### 形态

| 参数 | convar | 范围 | 说明 |
|---|---|---|---|
| 样式 | `cl_crosshairstyle` | 0–4 | 见下方样式说明 |
| 长度 | `cl_crosshairsize` | 0–25.5 | 四臂的长度 |
| 粗细 | `cl_crosshairthickness` | 0–25.5 | 四臂的宽度 |
| 间隙 | `cl_crosshairgap` | −12.8–12.7 | 四臂到中心的距离，**负值表示向中心收拢** |
| 固定间隙 | `cl_fixedcrosshairgap` | −12.8–12.7 | 关闭「间隙随武器变化」时生效 |
| 间隙随武器变化 | `cl_crosshairgap_useweaponvalue` | 开/关 | 开启时不同武器的间隙不同 |
| T 型 | `cl_crosshair_t` | 开/关 | 去掉上臂，只留下、左、右三臂 |
| 中心点 | `cl_crosshairdot` | 开/关 | 在正中心加一个点 |

样式取值：**0** 默认、**1** 静态（经典）、**2** 经典、**3** 内缩（精准）、**4** 动态。动态准星会随移动和开火向外扩张，静态样式则始终保持固定大小。

### 颜色

| 参数 | convar | 说明 |
|---|---|---|
| 颜色索引 | `cl_crosshaircolor` | 0 红 / 1 绿 / 2 黄 / 3 蓝 / 4 青 / 5 粉 / 6 自定义 |
| 红 / 绿 / 蓝 | `cl_crosshaircolor_r/g/b` | 0–255，**仅当索引为 6（自定义）时生效** |

这里有个容易踩的坑：颜色索引和 RGB 在码里是**两个独立存储的字段**。选了预设色（0–5）时游戏并不会改写 RGB，所以码里经常残留着与预设不符的 RGB 值 —— 我们实测抓到的真实码里就出现过「索引是 4（青）、RGB 却是 (0,255,0)（绿）」这种组合。**渲染时必须以索引为准，只有索引为 6 才读 RGB**，否则画出来的颜色和游戏里完全不同。

### 透明度与描边

| 参数 | convar | 范围 | 说明 |
|---|---|---|---|
| 启用透明度 | `cl_crosshairusealpha` | 开/关 | 关闭时准星完全不透明 |
| 透明度 | `cl_crosshairalpha` | 0–255 | 仅在启用时生效 |
| 启用描边 | `cl_crosshair_drawoutline` | 开/关 | 给准星加黑色外框，提升在亮背景上的可读性 |
| 描边粗细 | `cl_crosshair_outlinethickness` | 游戏内 0–3 | 编码上能表示到 127.5，但游戏 UI 只允许到 3 |

### 后坐力

| 参数 | convar | 说明 |
|---|---|---|
| 跟随后坐力 | `cl_crosshair_recoil` | 开启时准星会跟着后坐力移动，显示实际弹着点 |

### 动态准星的分裂参数

这 4 项**仅在样式为 4（动态）时影响外观**，但它们始终编码在码里，是选手的真实设置。

| 参数 | convar | 范围 | 说明 |
|---|---|---|---|
| 分裂距离 | `cl_crosshair_dynamic_splitdist` | 0–7 | 准星分裂的触发距离 |
| 内段透明度系数 | `cl_crosshair_dynamic_splitalpha_innermod` | 0–1.5 | 分裂后内段的透明度倍率 |
| 外段透明度系数 | `cl_crosshair_dynamic_splitalpha_outermod` | 0–1.5 | 分裂后外段的透明度倍率 |
| 最大分裂比 | `cl_crosshair_dynamic_maxdist_splitratio` | 0–1.5 | 最大分裂程度的比例 |

> 需要澄清一个流传的说法：有些资料声称这 4 项「不在准星码里、解出来永远是引擎默认值 2 / 0.8 / 0.4 / 1.5」。**这是错的。** 它们分别编码在第 8、10、11 字节的具体位段上（`bytes[8] & 7`、`(bytes[10] >> 4) / 10`、`(bytes[11] & 0xf) / 10`、`(bytes[11] >> 4) / 10`）。我们解码真实码得到过 `3 / 0.1 / 1 / 1` 这样明显不是默认值的组合，并且把它们原样重新编码可以字节级还原出同一个码。之所以会有那种误判，是因为只测试了自己生成的、恰好都用默认值的码。

## 修改参数时的取值陷阱

准星码用定长位段存储参数，所以**超出范围的值不会报错，而是静默回绕成完全不同的值**。实测：

| 输入 | 解码回来 | 发生了什么 |
|---|---|---|
| `length = 30` | **4.4** | 回绕 |
| `thickness = −1` | **24.6** | 回绕 |
| `alpha = 300` | **44** | 回绕 |
| `style = 9` | **style 变 1，且中心点开关被翻转** | 位污染，波及相邻字段 |
| `length = 2.34` | **2.3** | 向零截断 |

最后一条值得单独说：所有数值参数的取整是**向零截断**而不是四舍五入。`gap = −2.75` 会变成 `−2.7`（数学上的 floor 会给 −2.8），`outline` 的步进是 **0.5** 而不是 0.1（`2.74 → 2.5`、`3.25 → 3`）。

因此任何生成准星码的工具都必须先把输入钳制到合法范围、对齐到步进，再编码，最后把码解回来核对一遍参数是否一致 —— 本站的准星编辑器就是这么做的，不一致时宁可不给码。

## 怎么套用别人的准星

### 方式一：游戏内导入（推荐）

1. 复制准星码
2. 进入 CS2，打开「设置 → 准星」
3. 点「导入」，粘贴码，确认

### 方式二：CFG 文件

把 convar 写进 `autoexec.cfg`：

1. 在码详情页下载完整的 21 行 convar
2. 存成 `autoexec.cfg`，放到
   `Steam\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg\`
3. 在 CS2 的启动项里加 `+exec autoexec.cfg`

CFG 方式的好处是可以和其他设置（灵敏度、视频、按键绑定）放在一起统一管理。
